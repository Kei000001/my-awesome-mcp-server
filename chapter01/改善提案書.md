# 改善提案書

- 対象ログ: app.log
- 期間: 2024-01-20 10:00:00 〜 10:00:25（25秒間）
- ログ件数: 6件（INFO 3件 / ERROR 3件）
- 結果: 起動から25秒で異常終了

## 1. ログの時系列

| 時刻 | レベル | 内容 |
|---|---|---|
| 10:00:00 | INFO | アプリケーション起動 |
| 10:00:05 | ERROR | FileNotFoundException: config.ini が見つからない |
| 10:00:10 | INFO | リトライ開始 |
| 10:00:15 | ERROR | FileNotFoundException: config.ini が見つからない（再発） |
| 10:00:20 | ERROR | DatabaseException: 接続タイムアウト |
| 10:00:25 | INFO | アプリケーション終了 |

## 2. エラーパターン

### パターンA: 設定ファイルの読み込み失敗（2回）

- エラー: `FileNotFoundException: config.ini not found`
- 特徴: リトライ後も同じエラーが発生している。ファイルが存在しないという状況は待っても変わらないため、リトライでは解決しない種類のエラーである。
- 影響: 10秒間がリトライに費やされたうえ、最終的に失敗している。

### パターンB: データベース接続タイムアウト（1回）

- エラー: `DatabaseException: Connection timeout`
- 特徴: 設定ファイルの読み込みに2回失敗した直後に発生している。
- 推定原因: config.ini を読み込めないまま処理が続行され、接続先ホスト・ポート・認証情報などが未設定（またはデフォルト値）の状態で DB 接続を試みた可能性が高い。ただしログだけでは断定できないため、DB サーバー側の停止・ネットワーク障害も合わせて確認が必要。

### エラーの連鎖（推定）

```
config.ini が見つからない
  → リトライ（同じ理由で再び失敗）
    → 設定が読めないまま処理続行
      → 誤った接続情報で DB 接続を試行
        → Connection timeout
          → アプリケーション終了
```

根本原因はパターンAであり、パターンBはその二次障害である可能性が高い。

## 3. 改善提案

### 優先度: 高

#### 提案1: config.ini の配置と参照パスを確認する

- config.ini が実際に存在するか、アプリが参照しているパスを確認する。
- 相対パスで指定している場合、起動時のカレントディレクトリによって見つからなくなることがある。実行ファイルの場所を基準にした絶対パスで解決するか、環境変数（例: `APP_CONFIG_PATH`）でパスを指定できるようにする。
- エラーメッセージに探索したフルパスを出力し、原因を特定しやすくする。

```
ERROR: FileNotFoundException: config.ini not found (searched: /opt/app/config/config.ini)
```

#### 提案2: 設定ファイルがない場合は即座に停止する（Fail Fast）

- ファイルの欠落はリトライしても直らないため、FileNotFoundException はリトライ対象から外す。
- 設定の読み込みに失敗した時点で、原因と対処方法を示すメッセージを出して終了する。設定が不完全なまま後続処理（DB 接続など）に進ませない。
- これにより、二次障害（パターンB）を防ぎ、ログから根本原因が一目で分かるようになる。

#### 提案3: 設定ファイルのひな形を用意する

- `config.ini.example` をリポジトリに含め、README に「コピーして config.ini を作成する」手順を記載する。
- 初回セットアップ時の設定ファイル作成漏れを防ぐ。

### 優先度: 中

#### 提案4: 起動時に設定値を検証する

- DB 接続情報（ホスト・ポート・ユーザー名など）の必須項目が揃っているかを、接続を試みる前にチェックする。
- 不足している場合は「どの項目が足りないか」を明示してエラーにする。

#### 提案5: DB 接続のリトライとタイムアウトを見直す

- ネットワークの一時的な不調など、リトライで回復しうる DB 接続エラーに限ってリトライを行う。
- リトライ間隔は指数バックオフ（例: 1秒 → 2秒 → 4秒）とし、上限回数を設定する。
- 接続タイムアウト値を設定ファイルで調整できるようにする。

### 優先度: 低

#### 提案6: ログの情報量を増やす

- ERROR ログにスタックトレースや、DB 接続先のホスト名・ポート（パスワードは除く）を含める。
- リトライ時に「何回目のリトライか」「何をリトライしているか」を出力する。

```
INFO: Retrying config load (attempt 2/3)...
```

- 終了時に終了理由と終了コードを出力し、正常終了か異常終了かを区別できるようにする。

## 4. まとめ

| No. | 提案 | 優先度 | 対象パターン |
|---|---|---|---|
| 1 | config.ini の配置と参照パスの確認 | 高 | A |
| 2 | 設定ファイル欠落時の即時停止 | 高 | A, B |
| 3 | 設定ファイルのひな形の用意 | 高 | A |
| 4 | 起動時の設定値検証 | 中 | B |
| 5 | DB 接続のリトライ・タイムアウト見直し | 中 | B |
| 6 | ログの情報量の強化 | 低 | A, B |

まずは提案1で config.ini の問題を解消し、そのうえで DB 接続が成功するかを確認することを推奨する。config.ini の問題を解消しても DB タイムアウトが続く場合は、DB サーバーの稼働状況とネットワーク経路を別途調査する。
